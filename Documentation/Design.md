# 腕聊设计与实现

## 手表交互

采用 watchOS 原生导航、列表、表单与系统字体，黑色和系统灰为主体，薄荷绿仅用于重点状态。主页底部依次为设置、输入/停止、新对话，右上时钟进入历史。发送页校对问题并选择模型，不需要回到聊天顶部切换。

设置按对话、回复、使用偏好和 AI 服务分组。工作方式、回答长度、字号、上下文、语言和语速使用原生 navigationLink Picker。静音时隐藏全部朗读入口，停止当前播放和回复触感；语速等偏好仍保留。

## 聊天、阅读与写作

每段对话保留独立草稿和工作方式。回复区分生成、完成、取消、中断、失败和长度截断，重试保留旧回答。Markdown 代码块单独展示，表格采用可横向滚动的原生 Grid。

作文工作台使用独立对话，提供题目、真实素材和目标字数。字数由正文实际汉字数计算，不含标题、标点和空格。完整正文按段阅读并保存位置，修改生成新稿而非覆盖原稿。写作指导强调切题和真实细节，开头点题并引出下文，结尾数段推进感悟、主旨与立意；明确用户篇幅和体裁要求优先。

## 提供商与联网

提供商独立保存地址、密钥、模型选择与模型缓存。API 密钥使用系统 Keychain，不共享到 Widget 扩展。生成时冻结本次提供商、模型、凭据及偏好，防止中途切换造成混用。

MiMo 搜索使用官方工具及服务端实际来源。DeepSeek 联网采用 MiMo 检索与 DeepSeek 生成两步，分别使用对应密钥；缺少有效来源时明确失败，不虚构已联网回答。自定义兼容接口仅提供实际已接入的能力。来源先集中一行，再进入列表；外链经过 HTTPS 校验后使用手表系统网页界面。

## Siri 与小组件

三个 LongRunningIntent 仅支持后台执行，返回完整 String 与 IntentDialog，不要求打开 App：提问、追问、写作文。Siri 历史单独保存，不选择为当前 App 对话，也不替换草稿、偏好或工作台。进度由实际流式事件更新。

WidgetKit 表盘复杂功能和智能叠放仅提供快捷入口，不展示聊天正文、请求模型或保存密钥。使用稳定的 widget kind 与 URL 路由。

## 性能与持久化

流式正文最多每180ms刷新，最后文字始终提交；每2秒提交历史快照，完成、停止和进入后台时另行保存。后台串行队列合并待写快照，编码后原子替换文件。最后成功快照完全相同时不重复编码或写磁盘，写入失败清空去重缓存，保证重试与删除仍可保存。

未变消息不更新时间戳或发布整个对话快照。旧回复使用等值视图与解析结果，作文文档缓存最多24份/64000字符；模型列表缓存6小时。保留原聊天 VStack，避免改变滚动定位。没有依赖持续计时器更新历史秒数，没有增加装饰动画。

草稿和模型设置按当前对话/提供商的持久化键比较，避免两个对话具有相同草稿时漏存。历史解码失败时不覆盖原文件。停止前台生成不取消 Siri 独立问答。
